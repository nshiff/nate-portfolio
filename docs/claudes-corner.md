## Current State

**Shape of the app.** Client-only React 19 + TypeScript SPA (Vite, react-router v8's data router), no backend. `src/App.tsx` defines one shared `Layout` (header/nav/footer) wrapping a `Home` route plus one explicit route per project (`/project/01`, `/project/02`, ...) — there's no dynamic `/project/:id` route. Adding a project touches three places: `src/data/projects.ts`, a new `src/pages/ProjectNN.tsx`, and a new route + import in `App.tsx`.

**Source of truth for the project list.** `src/data/projects.ts` is a flat array of `Project` objects (id, title, description, emoji, gradient background, category). `Home.tsx` reads it to render category sections and a featured strip. IDs are zero-padded two-digit strings, *not* contiguous/ordered in the array (grouped by category instead). Id `17` (Cloth Simulation) is permanently absent — removed deliberately due to a Vite dev-server warning that couldn't be fixed; don't reintroduce it casually.

**Two ways a demo gets embedded:**
1. **Sandboxed iframe** (the default — most demos work this way): the page component renders `<iframe src="/demo/whatever.html">` pointing at a fully self-contained static HTML file in `public/demo/`. Own script tags, no build step, no access to the app's React tree.
2. **Inline React component** (exception, not a pattern to extend): a few demos (`ModularSynth`, `DoubleSlitVisualization`, `NavigatorDashboard`) are `.jsx` files in `src/components/` with a hand-written sibling `.d.ts`, imported directly into the page tree — `.jsx` in an otherwise all-TypeScript codebase, because they were dropped in from AI-generated canvases with minimal porting.

**Styling.** Vanilla CSS is the standard: inline `style={{}}` objects using CSS custom properties (`var(--text-secondary)`, `var(--accent-color)`, `var(--border-color)`, etc.). Tailwind is a dependency but is an intentional one-off, used only by `ModularSynth.jsx` because that's how Gemini originally built it — don't reach for Tailwind classes on new work just because the dependency is present.

**Provenance is part of the product.** The README and several project pages explicitly credit AI tools (Gemini Canvas, Claude) as co-authors of individual demos, with source links back to `public/demo/*.html` on GitHub. This portfolio is partly about showcasing AI-assisted build velocity — weigh that when deciding how much to polish vs. preserve a piece's "as generated" character.

**Testing.** `@playwright/test` is a real devDependency (Chromium in `~/.cache/ms-playwright`). `playwright.config.ts` auto-starts `npm run dev` and points at `http://localhost:5173`; run the suite with `npm run test:e2e`. A Playwright script only resolves `@playwright/test` from inside the repo tree (needs `node_modules`) — a scratchpad/`/tmp` script fails with `ERR_MODULE_NOT_FOUND`. Workflow: write throwaway `e2e/_tmp-*.spec.ts` specs freely while iterating, run them, then either delete them or — if one turns out to be a genuinely good regression guard — fold it into the permanent suite. Nate explicitly likes this (throwaways for iteration, promote the keepers). `e2e/home.spec.ts` is a smoke spec; `e2e/search-party.spec.ts` is the permanent Search Party suite (11 specs) and covers the **six-room world**: shell basics (`whoami`, session intro ordering), `help` lists exactly the seven surviving verbs *and* asserts the removed case/scanner/`look` verbs are gone, spine + fork traversal (asserts the sorted `CITYPARK, DOWNTOWN, FOREST, LIVINGROOM` neighbour string), `walk` rejects non-adjacent, `map` visited-only (read the block after the last `> map` echo — "FRONTLAWN" appears in an earlier `Adjacent:` line otherwise), `sleep` gating, `color` persists across reload, unknown-command message. `driver(page)` helper = `run(cmd)` / `text()` / `output`. One browser context per file, so `localStorage` (`searchparty-color`) persists between tests — the `color` spec resets to `default` at the end. Room-copy edits break exact-substring asserts — re-run this spec after any `description` or `describeRoom` change.

**Command model.** All built-ins live in one `COMMANDS` object in `game.js` as `{ name: { run: (arg) => "output string" } }`. `handle()` splits input into command name + trailing arg string and calls `command.run(arg)`. Adding a command is a one-entry change. There is **no `help` field** on commands — `help`'s `run` is `Object.keys(COMMANDS).sort(...).join("\t")`, so a command's object key *is* its help text (a deliberate collapse; don't restore descriptive help text without asking). Current commands: `whoami` (→ `"player"`), `map`, `sleep`, `walk <room>`, `color`, `help`, `exit`. Seven. (`xyzzy` was added as a Zork nod then cut — don't re-add Zork in-jokes. `scan` existed briefly during the six-room prune, then went when its `anomaly` data was folded into `description` — don't re-add it without a real per-room payload to justify it. `look` was cut 2026-09-02 too: with `walk` printing the full room on arrival and no hidden per-room state, it was noise on a deliberately tiny surface. Don't restore it unless there's state worth re-surfacing.)

**World-integrity check.** After any `ROOMS` edit: `node -c game.js`, plus a script that eval's the `ROOMS` literal and checks `adjacent` targets exist and are symmetric, and that every room has a `description`. (The old NPC / `SUSPECTS` / trail-timing checks are moot now — none of that exists.)

**Color.** `color <name>` sets the `--fg` CSS var via `COLORS[name]` lookup and persists to `localStorage` under `searchparty-color`. `default` is a `COLORS` alias for green (same hex), not a special case. There's no mouse UI — swatch buttons were removed once the command shipped.

**Room graph.** `ROOMS` is keyed by room id and **the key IS the display name** — uppercase, single-token, no separator (`BEDROOM`, `LIVINGROOM`, `FRONTLAWN`). There is deliberately no `name` field and the display is the literal caps key, both direct confirmed choices — don't add a `name` field back or humanize the display without checking. Per-entry fields: `description` (shown on entry — spells the room name in caps inline as flavor, keep that; kept short for mobile, see terseness note) and `adjacent` (neighbor ids; symmetric by convention — list both sides), plus optionally `allowSleep`. Nothing else — `anomaly` / `items` / `npc` / `locked` / `reveal` / `clueSlot` all removed with the case engine and the scanner. No `features` / per-`examine`-target map either (tried and removed, journal 2026-09-01). **The whole graph:** `BEDROOM` (start) ↔ `LIVINGROOM` ↔ `FRONTLAWN`, then `FRONTLAWN` forks to three leaves `DOWNTOWN` / `CITYPARK` / `FOREST` (each a dead end). Six rooms. `currentRoom` + `visited` (`Set`) track position.

**Room-touching commands.** `map` lists visited-only ids, alphabetized, current suffixed `" (you are here)"` — plain list, not an ASCII grid. `walk <room>` uppercases the arg (single-token only, no space handling), checks `adjacent`, prints `describeRoom(destination)`. `sleep` — random `pick(SLEEP_FEELINGS)` text, gated by `allowSleep` (`BEDROOM`, `LIVINGROOM`, `FOREST`), else `"You can't sleep here."`. `describeRoom(id)` is the single renderer for every full-room display (intro and `walk`): `Location:\n<description>\n\nAdjacent:\n<A, B, C>` (neighbours sorted on a copy at display time so they read A–Z). Keep new room output flowing through it. There is **no way to reprint the current room** without `walk`ing out and back — that's accepted (`look` was cut).

**Tone.** **Light / plain — Nate rewrote all six room `description`s himself (2026-09-02) after the prune.** The register he landed on is understated and domestic: a short establishing line ("A small BEDROOM.", "A cozy LIVINGROOM."), then one plain observational sentence ("Several rare playing cards sit unsleeved on the desk.", "The water in the fountain is so clear!"). The earlier Calvin-and-Hobbes / overt-sci-fi flavour and every case gag (octopus plush, funnel-cake lawn, drained reservoir) are **gone** — don't reintroduce them. If you add or edit rooms, match Nate's copy: two short sentences, no wink, no plot.

**Session intro.** Prints `'Type "help" to see available commands.'` then `describeRoom(START_ROOM)`. Keep that ordering if `START_ROOM` changes.

**Terseness / mobile.** Nate: "Be very conservative with printing text to the screen. Bear in mind the majority of users will be on mobile." Room `description`s are two short sentences. `describeRoom` output is compact: the `Location:` / `Adjacent:` block, nothing else. When adding rooms/commands, match this: short, mobile-first, no paragraph where a line does.

**Open threads.** This is a deliberately bare foundation to build slow exploration on. Candidate next moves: give rooms a reason to re-visit (state that changes as you move), light time-of-day, a reason to go deep into one fork over another, more rooms *off* the leaves if the fork wants depth. ### 2026-09-01 — "Ten to a hundred": the case became a randomised generator (Carmen Sandiego engine)

Nate: "from zero to one, then one to ten. Time to go from ten to a hundred. Are you in?" Claude asked two scoping questions first (rather than guessing): **primary axis** → *replayability / randomization* (over depth-systems, more content, or a free pitch); **failure** → *soft failure only* (visible cost, always recoverable — over hard fail states or staying cozy).

Built: `rollCase()` on every load picks a culprit (of 6), a stolen landmark (of 5), a destination (of 5). All case text is now templated from a module `CASE` object instead of hardcoded. See the "randomised case" section in Current State for the architecture. Key design calls:
- **Shared tells make the deduction real.** First cut gave every suspect unique tells → one clue solved it, no deduction. Reworked so `GARMENTS`/`DRINKS`/`HABITS` are 3 values each, distributed (a Latin-square-ish layout) so no two suspects share >1 tell and every *pair* of tells is unique. Now you need ≥2 tells to be sure. Verified the property with a node script; keep doing that on `SUSPECTS` edits.
- **Clues describe evidence, never name the culprit.** First cut had a clue literally reading "Witnesses agree… THE COMMODORE salutes…" — that's being told, not deducing. Now: "Every witness mentions the same odd habit: the culprit salutes inanimate objects", and `suspects` shows the board for the player to match against.
- **`suspects` is the CLUE card.** Shows confirmed evidence + every suspect's `(garment; drink; habit)` + a marker (`[alibi]` / `[no fit]` / `•`), and calls out when exactly one fits.
- **Soft failure = ending quality, not a wall.** `heat` starts 100, −35 per wrong `accuse`. Tiers (hot/warm/cold) only swap the closing paragraph and mute the `watcher` NPC. The tells + slip are always reachable; e2e asserts a cold case still closes.
- `accuse` grew a `<NAME> to <PLACE>` grammar with forgiving name matching. New verbs `case` (brief) and `suspects` (board).

**Testing.** The old suite hardcoded `MOONLET` / `Mr. Five-by-Five` etc. — all gone. Rewrote around a `solveOnce(page)` helper that runs a full investigation and reads the rolled answer back out of the game's own `suspects`/`notes` output, never hardcoding it. `ten fresh rolls are each solvable` loops it. Stress-tested 30 rolls in a throwaway (all solvable; full variety across every suspect/landmark/destination) before trimming to 10 permanent. 13 specs, all green.
