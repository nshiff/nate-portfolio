## Current State

**Shape of the app.** Client-only React 19 + TypeScript SPA (Vite, react-router v8's data router), no backend. `src/App.tsx` defines one shared `Layout` (header/nav/footer) wrapping a `Home` route plus one explicit route per project (`/project/01`, `/project/02`, ...) — there's no dynamic `/project/:id` route. Adding a project touches three places: `src/data/projects.ts`, a new `src/pages/ProjectNN.tsx`, and a new route + import in `App.tsx`.

**Source of truth for the project list.** `src/data/projects.ts` is a flat array of `Project` objects (id, title, description, emoji, gradient background, category). `Home.tsx` reads it to render category sections and a featured strip. IDs are zero-padded two-digit strings, *not* contiguous/ordered in the array (grouped by category instead). Id `17` (Cloth Simulation) is permanently absent — removed deliberately due to a Vite dev-server warning that couldn't be fixed; don't reintroduce it casually.

**Two ways a demo gets embedded:**
1. **Sandboxed iframe** (the default — most demos work this way): the page component renders `<iframe src="/demo/whatever.html">` pointing at a fully self-contained static HTML file in `public/demo/`. Own script tags, no build step, no access to the app's React tree.
2. **Inline React component** (exception, not a pattern to extend): a few demos (`ModularSynth`, `DoubleSlitVisualization`, `NavigatorDashboard`) are `.jsx` files in `src/components/` with a hand-written sibling `.d.ts`, imported directly into the page tree — `.jsx` in an otherwise all-TypeScript codebase, because they were dropped in from AI-generated canvases with minimal porting.

**Styling.** Vanilla CSS is the standard: inline `style={{}}` objects using CSS custom properties (`var(--text-secondary)`, `var(--accent-color)`, `var(--border-color)`, etc.). Tailwind is a dependency but is an intentional one-off, used only by `ModularSynth.jsx` because that's how Gemini originally built it — don't reach for Tailwind classes on new work just because the dependency is present.

**Provenance is part of the product.** The README and several project pages explicitly credit AI tools (Gemini Canvas, Claude) as co-authors of individual demos, with source links back to `public/demo/*.html` on GitHub. This portfolio is partly about showcasing AI-assisted build velocity — weigh that when deciding how much to polish vs. preserve a piece's "as generated" character.

**Testing.** `@playwright/test` is a real devDependency (Chromium in `~/.cache/ms-playwright`). `playwright.config.ts` auto-starts `npm run dev` and points at `http://localhost:5173`; run the suite with `npm run test:e2e`. A Playwright script only resolves `@playwright/test` from inside the repo tree (needs `node_modules`) — a scratchpad/`/tmp` script fails with `ERR_MODULE_NOT_FOUND`. Workflow: write throwaway `e2e/_tmp-*.spec.ts` specs freely while iterating, run them, then either delete them or — if one turns out to be a genuinely good regression guard — fold it into the permanent suite. Nate explicitly likes this (throwaways for iteration, promote the keepers). `e2e/home.spec.ts` is a smoke spec; `e2e/search-party.spec.ts` is the permanent Search Party suite and, as of 2026-09-01, covers **game mechanics**, not just smoke: the shell basics (`whoami`, a `walk` traversal, `sleep` gating) plus the henchman case (help lists the case verbs, `scan` needs the scanner, the `grey coin` gate on `PUMPROOM`, `talk`→`notes` clue capture, and the full no-proof→scan-RESERVOIR→wrong-accusation→correct-accusation win path ending in a disabled `#cmd`). It has a `driver(page)` helper (`run(cmd)` / `text()` / `output`) — reuse it for new cases. Drives the game by `#cmd.fill(...).press('Enter')`, asserts on `#output` text. Playwright reuses one browser context per file, so `localStorage` (`searchparty-color`) persists between tests here — a test needing a clean color state handles that itself. **Room-copy edits break exact-substring asserts** — re-run this spec after any description change (a dropped comma in OUTLOOK once did).

**Project 20** is **Search Party**, a Zork-like, living in `public/demo/zork-roguelike/` (directory name is stale — predates the current name, don't read anything into it). Two files: `index.html` (dark terminal UI — `#0a0a0a` bg, JetBrains Mono, bold 1.125rem output/input) and `game.js` (the whole game — a short IIFE, read it before changing it). **Direction (2026-09-01):** started as a Carmen Sandiego / CLUE henchman tracker built *gameplay-feel-first* (command vocabulary before mechanics). That vocabulary phase is done — as of the same day, Nate said "let loose… go wild," and a full case layer landed in one pass: items, a scanner, a notebook, NPCs, a locked door, and a win state. Still incremental at heart (see `feedback_iterative_style_audit`), just no longer one-verb-at-a-time.

**Command model.** All built-ins live in one `COMMANDS` object in `game.js` as `{ name: { run: (arg) => "output string" } }`. `handle()` splits input into command name + trailing arg string and calls `command.run(arg)`. Adding a command is a one-entry change. There is **no `help` field** on commands — `help`'s `run` is `Object.keys(COMMANDS).sort(...).join("\t")`, so a command's object key *is* its help text. This was a deliberate two-step collapse (descriptive strings → bare names → reading the key); don't restore descriptive help text without asking. Current commands: `whoami` (→ `"player"`), `color <green|amber|white|default>`, `map`, `sleep`, `walk <room>`, `look`, `scan`, `take <item>`, `drop <item>`, `inventory`, `talk [who]`, `notes`, `accuse <PLACE>`, `help`, `exit`. (`xyzzy` was added as a Zork nod then cut — Nate felt it broke the established tone; don't re-add Zork in-jokes.)

**The case layer (2026-09-01, "go wild" pass).** The game is now winnable. Moving parts, all in `game.js`:
- **Items.** `ROOMS[x].items` is an array of lowercase item names. `take`/`drop` move strings between a room's `items` and the `inventory` `Set`; `inventory` starts with `"pocket scanner"` and it can't be dropped (past-you joke). `describeRoom` appends `"You can see: …"` when a room has items. Taking certain items calls `noteClue(...)`.
- **`scan`.** Needs `"pocket scanner"` in inventory. Prints `ROOMS[currentRoom].anomaly` — a deadpan sensor readout that carries the sci-fi payload the descriptions only hint at. Every room has one. `RESERVOIR` additionally has `reveal: "destination"`: scanning it is the *only* way to learn the answer (`DESTINATION` const = `"MOONLET"`), and it writes that clue into the notebook. `scan` is the "senses" verb that `examine` failed to be — one implicit target (the room), nothing to miss.
- **Notebook.** `notebook` (ordered array) + `noteClue(text)` (de-dupes). `notes` prints it numbered. Clues accrue from `talk`, from `take` on key items, from `passiveClues()` (fires on `walk`, keyed by room + inventory), and from scanning `RESERVOIR`. This is the CLUE deduction surface.
- **NPCs.** `NPCS` object, keyed by a short id; `ROOMS[x].npc` holds that id (kept in sync both directions — the world-check script verifies it). `talk [who]` prints `npc.lines` and drops `npc.clue`. Three so far: `operator` (STREETFAIR), `barista` (CAFE), `regular` (TAVERN). `describeRoom` appends `"Someone here you could talk to."` when `room.npc` is set.
- **Locked doors.** `ROOMS[x].locked = { needs: "<item>", hint: "<text>" }`. `walk` into a locked room without the item prints the hint and refuses; with the item, prints a CLUNK line then the room. Only `PUMPROOM` uses it (`needs: "grey coin"`, which you grab from `FOUNTAIN`). This is the `allowSleep` pattern generalized — copy `locked` for any future gated room.
- **Win state.** `won` (module `let`). `accuse <PLACE>` uppercases the arg: no proof (no notebook clue containing `DESTINATION`) → narrator ribs you; proof but wrong place → "WRONG", flavor about the rock drifting further; correct → win screen, `won = true`, `input.disabled = true`. `exit` checks `won` for alternate text.

**World-integrity check.** After any `ROOMS`/`NPCS` edit run: `node -c game.js` for syntax, plus a script that eval's the `ROOMS` and `NPCS` literals and asserts (a) every `adjacent` target exists and is symmetric, (b) every `room.npc` has an `NPCS` def and vice-versa, (c) `NPCS[k].room` points back to a room whose `npc === k`. This has caught a duplicate room block and would catch NPC desync.

**Color.** `color <name>` sets the `--fg` CSS var via `COLORS[name]` lookup and persists to `localStorage` under `searchparty-color`. `default` is a `COLORS` alias for green (same hex), not a special case. There's no mouse UI — swatch buttons were removed once the command shipped.

**Room graph.** `ROOMS` is keyed by room id and **the key IS the display name** — uppercase, single-token, no separator (`BEDROOM`, `LIVINGROOM`, `FRONTLAWN`). There is deliberately no `name` field and the display is the literal caps key, both direct confirmed choices — don't add a `name` field back or humanize the display without checking. Per-entry fields: `description` (shown on entry — spells the room name in caps inline as flavor, keep that; kept short for mobile, see terseness note), `adjacent` (neighbor ids; symmetric by convention — list both sides), and optionally `anomaly` (scanner text — every room has one; this is where verbose detail lives since it's opt-in), `items` (array), `npc` (an `NPCS` key), `locked` (`{ needs, hint }`), `reveal` (`"destination"` on `RESERVOIR` only), and `allowSleep`. No `features` / per-`examine`-target map — tried and removed (journal 2026-09-01). Base shape: `BEDROOM` (start) ↔ `LIVINGROOM` ↔ `FRONTLAWN`, then `FRONTLAWN` branches to `DOWNTOWN` / `CITYPARK` / `FOREST`, each branching to three leaves: `DOWNTOWN`→`CAFE`/`STREETFAIR`/`TAVERN`, `CITYPARK`→`BIGTREE`/`FOUNTAIN`/`OUTLOOK`, `FOREST`→`STREAM`/`TREEHOUSE`/`VERYBIGTREE`. **Not a pure tree:** `STREETFAIR`→`FUNHOUSE`/`TICKETBOOTH`/`BACKLOT` and `FOUNTAIN`→`UNDERPASS`→`PUMPROOM`→`RESERVOIR`, with `BACKLOT` ↔ `UNDERPASS` ↔ `FOUNTAIN` closing an underground loop. 21 rooms. `currentRoom` + `visited` (`Set`) track position.

**Room-touching commands.** `map` lists visited-only ids, alphabetized, current suffixed `" (you are here)"` — plain list, not an ASCII grid. `walk <room>` uppercases the arg (single-token only, no space handling), checks `adjacent`, honours `locked`, calls `passiveClues()`, prints `describeRoom(destination)`. `sleep` — random `pick(SLEEP_FEELINGS)` text, gated by `allowSleep` (`BEDROOM`, `LIVINGROOM`, `BIGTREE`, `TREEHOUSE`), else `"You can't sleep here."`. `look` returns `describeRoom(currentRoom)` — no move, no state change. `describeRoom(id)` is the single renderer for every full-room display (intro, `walk`, `look`) — keep new room output flowing through it. It sorts `adjacent` on a copy at display time so neighbours read A–Z regardless of authoring order, and appends the compact `Here: <items>` / `Someone to talk to.` lines.

**Tone (2026-09-01).** **Silly / light — do not write this straight.** Nate's reference points: Carmen Sandiego, CLUE, *Calvin and Hobbes*, *Inspector Gadget*, "even a bit goofy is fine." Claude named **Calvin and Hobbes** as the primary influence and Nate agreed — the specific move is *treat the cosmic with total domestic casualness* (Calvin's cardboard box is a time machine labelled in crayon; here, an interstellar launch console is hand-labelled in masking tape and someone's written "DO NOT" on one button). The plot is genuinely overt sci-fi (the henchman is off-world, the fair was cover, the RESERVOIR was drained and re-lined as a launch cradle, the 40-tonne OBELISK monument is *gone*, destination `MOONLET`), but never played for menace.
- **The henchman:** "Mr. Five-by-Five" / "F5B", a bumbling man in a black turtleneck who follows a numbered checklist ending "ACT NATURAL", drinks warm milk in the same CAFE booth for six years, tips in grey off-world coins, and leaves a sticky note reading "BORROWED THE PLANET'S GARAGE, BACK LATER".
- **Running gags that stitch the trail:** the black turtleneck (FUNHOUSE mirror → snagged on BACKLOT door → folded on the RESERVOIR post — and you can `take` it); the purple octopus plush (a town-wide transponder network, played as everyone pretending they always had one; also a `sleep` line); backwards/disabled fair attractions (Ferris wheel stuck since Tuesday, WISHING TEMPORARILY DISABLED); the OBELISK (plaque with no monument → carved rectangle in BIGTREE → drag marks → the cargo slip).
- `BEDROOM` opens on a case file ("one (1) missing henchman") to set premise + tone turn one. Every room's `anomaly` (scanner) line is written in the same deadpan key. Keep all new content here — no grimdark, no straight menace.

**Session intro.** Prints `'Type "help" to see available commands.'` then `describeRoom(START_ROOM)`. Keep that ordering if `START_ROOM` changes. (A "New here: scan/notes/accuse…" second sentence was tried and cut — see terseness note below.)

**Terseness / mobile (2026-09-01).** Nate: "Be very conservative with printing text to the screen. Bear in mind the majority of users will be on mobile." So: room `description`s were trimmed to ≤ ~240 chars (was up to 320) — keep the plot beat + one gag, push detail into the `anomaly` (scanner) line which is opt-in. `describeRoom` output is compact: `Exits: A, B, C` on one line (not "You are adjacent to:" + a stacked list), then optional single lines `Here: <items>` and `Someone to talk to.`. NPC `lines`, the win screen, `accuse`/`scan`/`walk` prompts, `inventory` (now comma-joined, not stacked) were all shortened. `anomaly` strings were left long — you only see them on demand. When adding rooms/commands, match this: short, mobile-first, no paragraph where a line does.

**Open threads / unused hooks.** Lots of `anomaly` and room flavor points at content not yet mechanised: the STREAM relay ("PROPERTY OF F5B — PLEASE DO NOT SKIP"), the VERYBIGTREE stakeout closet and TREEHOUSE cork board (someone has been *watching* the henchman for six years — a second party, undefined), the FOREST carrier tone, the `tape roll` item in PUMPROOM (takeable, no use yet), the `octopus plush`/`clipboard`/`logbook` items (clue-on-take, otherwise inert). Room for a `use <item>` verb, a second NPC/antagonist (the watcher), or more `accuse`-style branches. Nothing here is a loose end that needs tying — they're deliberate seeds.
