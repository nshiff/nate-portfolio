It has two parts, and they serve different purposes:

If something you're about to log is really just "the current architecture changed," update Current State and don't also spend a journal entry restating it. Journal entries are for the *reasoning*, the *override*, the *gotcha* — not a changelog of every edit.

## Current State

**Shape of the app.** Client-only React 19 + TypeScript SPA (Vite, react-router v8's data router), no backend. `src/App.tsx` defines one shared `Layout` (header/nav/footer) wrapping a `Home` route plus one explicit route per project (`/project/01`, `/project/02`, ...) — there's no dynamic `/project/:id` route. Adding a project touches three places: `src/data/projects.ts`, a new `src/pages/ProjectNN.tsx`, and a new route + import in `App.tsx`.

**Source of truth for the project list.** `src/data/projects.ts` is a flat array of `Project` objects (id, title, description, emoji, gradient background, category). `Home.tsx` reads it to render category sections and a featured strip. IDs are zero-padded two-digit strings, *not* contiguous/ordered in the array (grouped by category instead). Id `17` (Cloth Simulation) is permanently absent — removed deliberately due to a Vite dev-server warning that couldn't be fixed; don't reintroduce it casually.

**Two ways a demo gets embedded:**
1. **Sandboxed iframe** (the default — most demos work this way): the page component renders `<iframe src="/demo/whatever.html">` pointing at a fully self-contained static HTML file in `public/demo/`. Own script tags, no build step, no access to the app's React tree.
2. **Inline React component** (exception, not a pattern to extend): a few demos (`ModularSynth`, `DoubleSlitVisualization`, `NavigatorDashboard`) are `.jsx` files in `src/components/` with a hand-written sibling `.d.ts`, imported directly into the page tree — `.jsx` in an otherwise all-TypeScript codebase, because they were dropped in from AI-generated canvases with minimal porting.

**Styling.** Vanilla CSS is the standard: inline `style={{}}` objects using CSS custom properties (`var(--text-secondary)`, `var(--accent-color)`, `var(--border-color)`, etc.). Tailwind is a dependency but is an intentional one-off, used only by `ModularSynth.jsx` because that's how Gemini originally built it — don't reach for Tailwind classes on new work just because the dependency is present.

**Provenance is part of the product.** The README and several project pages explicitly credit AI tools (Gemini Canvas, Claude) as co-authors of individual demos, with source links back to `public/demo/*.html` on GitHub. This portfolio is partly about showcasing AI-assisted build velocity — weigh that when deciding how much to polish vs. preserve a piece's "as generated" character.

**Testing.** `@playwright/test` is a real devDependency (Chromium in `~/.cache/ms-playwright`). `playwright.config.ts` auto-starts `npm run dev` and points at `http://localhost:5173`; run the suite with `npm run test:e2e`. A Playwright script only resolves `@playwright/test` from inside the repo tree (needs `node_modules`) — a scratchpad/`/tmp` script fails with `ERR_MODULE_NOT_FOUND`. For a one-off visual check, write a throwaway `e2e/*.spec.ts`, run it, then delete it rather than leaving it in the permanent suite. `e2e/home.spec.ts` is the pattern for a real, permanent spec (navigate, assert visible text/roles) — keep new permanent specs low-effort/smoke-level unless asked for more. `e2e/search-party.spec.ts` is the permanent home for Search Party specs (currently three: `whoami` → `"player"`; a full BEDROOM→LIVINGROOM→FRONTLAWN→CITYPARK→OUTLOOK `walk` traversal; `sleep` allowed in LIVINGROOM, refused on FRONTLAWN); it drives the game by `page.locator('#cmd').fill(...).press('Enter')` and asserts on `#output` text. Playwright reuses one browser context per file, so `localStorage` (`searchparty-color`) persists between tests in this file — a test that depends on a clean color state has to handle that itself.

**Project 20** is **Search Party**, a Zork-like, living in `public/demo/zork-roguelike/` (directory name is stale — predates the current name, don't read anything into it). Two files: `index.html` (dark terminal UI — `#0a0a0a` bg, JetBrains Mono, bold 1.125rem output/input) and `game.js` (the whole game — a short IIFE, read it before changing it). It's an early prototype that's been torn down and rebuilt more than once; treat the code as current truth and the journal as history, not the other way round.

**Direction (2026-09-01):** rebuild toward a Carmen Sandiego / Clue-style henchman tracker, but *gameplay feel first* — nail the command vocabulary of a Zork-like before any game logic, characters, or case content. Commands land one at a time as Nate asks for them. Don't push to lock scope early (see the `feedback_iterative_style_audit` memory).

**Command model.** All built-ins live in one `COMMANDS` object in `game.js` as `{ name: { run: (arg) => "output string" } }`. `handle()` splits input into command name + trailing arg string and calls `command.run(arg)`. Adding a command is a one-entry change. There is **no `help` field** on commands — `help`'s `run` is `Object.keys(COMMANDS).sort(...).join("\t")`, so a command's object key *is* its help text. This was a deliberate two-step collapse (descriptive strings → bare names → reading the key); don't restore descriptive help text without asking. Current commands: `whoami` (→ `"player"`), `color <green|amber|white|default>`, `map`, `sleep`, `walk <room>`, `look`, `help`, `exit`.

**Color.** `color <name>` sets the `--fg` CSS var via `COLORS[name]` lookup and persists to `localStorage` under `searchparty-color`. `default` is a `COLORS` alias for green (same hex), not a special case. There's no mouse UI — swatch buttons were removed once the command shipped.

**Room graph.** `ROOMS` is keyed by room id and **the key IS the display name** — uppercase, single-token, no separator (`BEDROOM`, `LIVINGROOM`, `FRONTLAWN`). There is deliberately no `name` field and the display is the literal caps key, both direct confirmed choices — don't add a `name` field back or humanize the display without checking. Each entry has just `description` (shown on entry — spells the room name in caps inline as flavor, keep that; for the newer sci-fi rooms it's 2–3 sentences carrying the whole beat, since there's no sub-room detail layer), `adjacent` (neighbor room ids; symmetric by convention — list both sides of an edge), and optional gameplay flags checked against `ROOMS[currentRoom]` (currently just `allowSleep`). No `features` / per-room detail map — that was tried and removed (see journal 2026-09-01). Base shape: `BEDROOM` (start) ↔ `LIVINGROOM` ↔ `FRONTLAWN`, then `FRONTLAWN` branches to `DOWNTOWN` / `CITYPARK` / `FOREST`, and each branches again to three leaves: `DOWNTOWN`→`CAFE`/`STREETFAIR`/`TAVERN`, `CITYPARK`→`BIGTREE`/`FOUNTAIN`/`OUTLOOK`, `FOREST`→`STREAM`/`TREEHOUSE`/`VERYBIGTREE`. **No longer a pure tree:** `STREETFAIR` and `FOUNTAIN` each grew a 3-room sci-fi branch (`STREETFAIR`→`FUNHOUSE`/`TICKETBOOTH`/`BACKLOT`; `FOUNTAIN`→`UNDERPASS`→`PUMPROOM`→`RESERVOIR`), and `BACKLOT` ↔ `UNDERPASS` ↔ `FOUNTAIN` closes an underground **loop** back to the park side — so `walk` is now genuine navigation with cycles, not press-forward. 21 rooms total. `currentRoom` (module `let`) and `visited` (`Set`, seeded with `START_ROOM`) track state. Grows one room at a time; run `node -c` + an adjacency-symmetry check after edits.

**Room-touching commands.** `map` lists visited-only room ids, `.sort()`ed alphabetically, current room suffixed `" (you are here)"` — plain list, chosen over an ASCII grid. `walk <room>` uppercases the arg (no space-handling — single-token rooms only, so `walk livingroom` works and `walk living room` deliberately doesn't), checks `ROOMS[currentRoom].adjacent`, then moves and prints `describeRoom(destination)`. `sleep` returns random flavor text via the `pick()` helper, gated by `allowSleep` — currently `BEDROOM`, `LIVINGROOM`, plus `BIGTREE` and `TREEHOUSE` (Nate opted the two tree rooms in; most outdoor rooms lack it) — prints `"You can't sleep here."` otherwise. `allowSleep` is the pattern to copy for any future room-gated command. `describeRoom(id)` is the single renderer every full-room display goes through (session intro + `walk`) so they can't drift — keep new room output flowing through it. It sorts `adjacent` alphabetically at display time (`[...room.adjacent].sort()`, on a copy — data order in `ROOMS` is left untouched), so neighbor lists always read A–Z regardless of authoring order.

**`look`.** Returns `describeRoom(currentRoom)` — re-prints the room, no move, no state change. The only "senses" verb; `examine` was tried alongside it and cut (journal 2026-09-01) — too much per-room data for players to track without knowing the verb existed.

**Tone (2026-09-01).** **Silly / light — do not write this straight.** Reference points Nate gave: Carmen Sandiego, CLUE, *Calvin and Hobbes*, *Inspector Gadget*, "even a bit goofy is fine." The plot is still overt sci-fi (the henchman isn't from here, the street fair was cover, the RESERVOIR was drained and re-lined as a launch cradle and the thing that sat in it is *gone*), but every description plays it for laughs: a bumbling henchman in a black turtleneck who leaves clipboards reading STEP 4: ACT NATURAL and a sticky note reading "BORROWED THE PLANET'S GARAGE, BACK LATER"; municipal equipment hand-labeled in masking tape (UP / ALSO UP / DOWN (14 HRS) / DO NOT); a recurring purple octopus plush; a wry narrator. Running gags that tie the trail together: the black turtleneck (snagged in FUNHOUSE mirror → BACKLOT door → folded on the RESERVOIR post), the octopus plush (STREETFAIR, and a `sleep` line), backwards/disabled fair attractions (Ferris wheel stuck since Tuesday, WISHING TEMPORARILY DISABLED). `BEDROOM` opens on a case file ("one (1) missing henchman") to set premise + tone from turn one. Base house/park rooms are mostly still terse originals; `BEDROOM` and `OUTLOOK` were nudged into the lighter register, the rest can follow if it comes up. Keep new content in this key — no grimdark, no playing the sci-fi menace straight.

**Session intro.** Prints the `help` tip, then `describeRoom(START_ROOM)`. Keep that ordering if `START_ROOM` changes.
